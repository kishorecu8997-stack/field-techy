# Scrum Board

The Scrum Board is a visual tool (e.g., GitHub Projects or Jira) used to track user stories and tasks in Field Techy, ensuring transparency and progress visibility.

## Maintenance Hygiene
- **Daily Updates:** Assignees update status at the start/end of the day.
- **Status Accuracy:** Reflect true progress; avoid misleading statuses.
- **Clean Board:** Archive completed items weekly; remove obsolete tasks.
- **Visibility:** Ensure all team members can access and understand the board.
- **Burndown Tracking:** Monitor sprint progress and adjust as needed.

## Rules
- **Updates:** Only the assignee or [PO](roles.md) can update a user story. Team members should not modify others' assigned stories.
- **PR Assignment:** PR assignee is the same as the user story assignee, unless [PO](roles.md) assigns otherwise.
- **PR Responsibility:** PR assignee must address review comments and get approval within two days. See [Code Review and Assignment](code-review-and-assignment.md).
- **Violations:** Any breach of board or branch rules leads to immediate escalation to [PO](roles.md) or [Scrum Master](roles.md).
- **Escalation Triggers:** Failure to meet end dates without prior indication, or PRs not merged within two days ([escalated by QA to PO](escalation.md)).

These rules maintain accountability and efficiency.
