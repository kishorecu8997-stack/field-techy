# SDLC Document

This section provides a comprehensive Software Development Life Cycle (SDLC) document tailored to the Field Techy platform, emphasizing the Scrum framework for agile development.

## Purpose
- To outline the end-to-end SDLC process, from ideation to deployment and maintenance.
- To define roles, events, artifacts, and best practices for Scrum-based development.
- To integrate QA, code reviews, tools, and workflows for consistent execution.
- To support onboarding, process improvement, and alignment with project goals and Definition of Done (DoD).

## Structure

| Section | Description |
|---------|-------------|

| [**Artifacts**](artifacts.md) | Management of Product Backlog, Sprint Backlog, Increment, work hierarchy, and DoD. |
| [**Events**](events.md) | Details on Sprint Planning, Daily Scrum, Sprint Review, and Retrospective. |
| [**Phases Mapping**](phases-mapping.md) | SDLC phases aligned with Scrum cycles, including responsibilities and timelines. |

| [**Code Review and Assignment**](code-review-and-assignment.md) | PR guidelines, single assignee principle, and CI/CD integration. |
| [**QA Processes**](qa-processes.md) | Testing strategies, QA in events, test design/reporting per sprint, and defect handling. |
| [**Escalation of Issues**](escalation.md) | Process for escalating blockers and performance concerns to PO. |
| [**Scrum Board**](scrum-board.md) | Guidelines for maintaining the Scrum Board, hygiene, and rules for updates and assignments. |

## Key Highlights
- **Scrum Focus:** Emphasizes iterative development with time-boxed sprints.
- **QA Integration:** Testing embedded in each sprint for early defect detection.
- **Tooling:** Git Flow for branching, GitHub for collaboration, with back-merges for synchronization.
- **Field Techy Context:** Examples tied to client portals, engineer management, and backend services.

This document is versioned, reviewed by stakeholders, and updated with process refinements. Refer to sub-pages for detailed sections.
